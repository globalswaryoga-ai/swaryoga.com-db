API 404/400 ERRORS - ROOT CAUSE ANALYSIS & FIXES
================================================

ERRORS REPORTED:
1. GET /api/admin/crm/whatsapp/qr-bridge?path=%2Fchats  → 404 (Not Found)
2. POST /api/admin/crm/messages  → 400 (Bad Request)

ROOT CAUSE #1: Missing /chats Endpoint on Bridge
─────────────────────────────────────────────────
Status: ❌ CRITICAL - Endpoint not registered on EC2 bridge

Diagnostic Results:
  ✅ Bridge /status → 200 OK (bridge is running)
  ❌ Bridge /chats  → 404 Not Found (route missing)
  ❌ Bridge /messages/all → 500 Error

The /chats endpoint code exists in services/whatsapp-web/index.js line 766
BUT the deployed bridge service on EC2 (52.91.198.23:3333) doesn't have it.

This means:
  • Bridge was deployed with old/incomplete code
  • Bridge service may have crashed/restarted
  • Route not properly registered in current version

Frontend Impact:
  • App tries: bridgeFetch('/chats')
  • Gets: 404 from bridge
  • Proxy: /api/admin/crm/whatsapp/qr-bridge?path=%2Fchats returns 404
  • Result: Chat list fails to load


ROOT CAUSE #2: Missing Required Fields
───────────────────────────────────────
Status: ⚠️  Validation Error - Endpoint requirements not met

The /api/admin/crm/messages PUT endpoint requires:
  • action: 'markThreadAsRead'
  • EITHER leadId OR phoneNumber (at least one required)

Frontend sends request with:
  • leadId: activeLeadId (could be undefined)
  • phoneNumber: activePhone (could be undefined)

If BOTH are undefined → endpoint returns 400 "Missing: leadId or phoneNumber"

Frontend code (line 1378-1383):
  if (activeLeadId || activePhone) {
    fetch('/api/admin/crm/messages', {
      action: 'markThreadAsRead',
      leadId: activeLeadId,        // could be null
      phoneNumber: activePhone      // could be null
    })
  }

If the logic was inverted or variables not set → 400 error
